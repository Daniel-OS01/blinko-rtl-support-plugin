## 2025-02-20 - Cache DOM Selector Validation Outside MutationObservers
**Learning:** During heavy DOM manipulations (like typing in contenteditable areas or large UI re-renders), evaluating configuration-dependent matching logic inside a `MutationObserver` callback causes massive performance bottlenecks. In `rtlService.ts`, the code originally parsed arrays, re-evaluated valid selectors with `try...catch`, and called `document.querySelector` on every mutation batch, slowing down the main thread significantly.
**Action:** Extract expensive, configuration-dependent logic (like calculating safe selector strings) out of the `MutationObserver` closure entirely. Cache these values at setup time (e.g., in `setupObserver()`) so they only re-run when settings change, ensuring the observer callback only checks `matches()` against a pre-calculated list of valid selectors.
