## 2025-04-09 - Caching DOM Validations Outside MutationObserver
**Learning:** In a MutationObserver callback (like in `src/services/rtlService.ts`), checking DOM structure configuration (such as resolving active selectors, and then querying the DOM using `document.querySelector` inside a try-catch to validate their safety) per mutation creates a massive performance bottleneck. The bottleneck is amplified during UI interactions where childList/characterData events continuously fire.
**Action:** Lift configuration-dependent filtering, list joining, and expensive validating logic outside the actual `new MutationObserver((mutations) => { ... })` definition if they don't require information from the mutation batch itself. This limits expensive DOM querying to observer instantiation/setup instead of on every tree mutation.
