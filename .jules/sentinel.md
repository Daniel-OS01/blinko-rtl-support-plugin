## 2025-02-27 - Regex String Replacement Injection
**Vulnerability:** A string replacement vulnerability exists where `String.prototype.replace(regex, string)` fails to properly escape replacement strings. If user-controlled data (`content`) is used as the replacement string without escaping or utilizing an arrow function callback (`() => content`), inputs containing regex special tokens like `$&` result in injection attacks where the placeholder or other segments of the original string are inadvertently mirrored.
**Learning:** `String.prototype.replace()` interprets `$` tokens (`$&`, `$'`, `` $` ``) as capture directives, exposing logic bugs and potentially corrupting configurations, scripts, or AI prompts if the replacement string is dynamically supplied by the user.
**Prevention:** Avoid injecting variables directly into the second argument of `.replace()`. Instead, always use a replacer callback arrow function (e.g., `.replace(/\{var\}/g, () => value)`) when replacing strings with untrusted or external input, which guarantees literal string placement.
