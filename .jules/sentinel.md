## 2026-03-30 - Template Manipulation via Regex Replacement Patterns
**Vulnerability:** The `AIPostService.buildPrompt()` function used regex `String.prototype.replace()` without escaping special replacement patterns like `$&` or `$'` in user's note `content` and `tags` to build prompts for the AI backend.
**Learning:** If user input contains special regex replacement strings (e.g. `$&`), `replace()` substitutes the matched substring instead of the literal `$&`. A malicious note could exploit this behavior to duplicate matched strings, potentially manipulating the resulting prompt sent to the LLM backend (a form of prompt injection). Replacing static strings via `innerHTML` is often just security theater; focusing on logical data flow vulnerabilities provides real value.
**Prevention:** When injecting user input into templates using `String.prototype.replace()`, always use a replacer arrow function (e.g., `replace(/pattern/g, () => userInput)`) instead of direct string replacement to ensure that the input is treated as a literal string.
